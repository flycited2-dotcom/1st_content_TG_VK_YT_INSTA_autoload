# Готовые карточки Avito → подтверждение в Telegram

Импорт уже сгенерированных карточек и УТП в **существующую** очередь подтверждения
Контент-завода. Публикацию в канал по-прежнему делает только владелец кнопкой ✅ под
превью; импортёр публиковать не умеет и не должен.

Задача и границы — [AVITO-TELEGRAM-TASK.md](AVITO-TELEGRAM-TASK.md). Здесь — как запускать.

## 1. Что делает и чего не делает

| Делает | Не делает |
|---|---|
| Проверяет манифест партии и отбраковывает всё сомнительное | Не ходит в генератор карточек и не перегенерирует их |
| Копирует карточку в свой стабильный каталог | Не двигает и не удаляет оригинал |
| Собирает подпись (модель, цена, УТП, CTA) | Не считает наценку и не округляет цену |
| Кладёт пост в `ConfirmStore` со статусом `pending` | Не трогает строки `pending` / `rejected` / `published` |
| Шлёт превью с кнопками ✅/❌ **только** в review-чат | Не шлёт в боевой канал, не нажимает approve, не пишет `PublishState` |
| Записывает реальный review `message_id` в свой журнал | Не поллит Telegram и не поднимает второго бота |

Существующие файлы (`publish/telegram.py`, `bot/*`, `orchestrator/confirm_store.py`)
не изменялись: approve-путь остаётся ровно тем же, что и был.

## 2. Контракт манифеста (`schema_version: 1`)

Манифест собирает сторона, у которой есть доступ к источникам (генератор карточек,
фид, отчёт по наценкам). Импортёр ничего не додумывает: неполнота = отказ по позиции.

```jsonc
{
  "schema_version": 1,
  "batch_id": "b-2026-08-30",                  // [\w.-]{1,64}, попадает в имя каталога копий
  "cards_root": "/opt/content-factory/state/avito-source-cards",   // абсолютный, существует
  "feed": {"url": "https://splithome.ru/static/avito-feed.xml",
           "sha256": "<64 hex>",               // фиксирует версию источника цен
           "fetched_at": "2026-08-30T21:30:00+03:00"},
  "items": [{
    "source_id": "AV-100234",                  // стабильный id объявления, без пробелов
    "sku": "NC-0012345",                       // точный артикул…
    "series_key": "",                          // …или ключ серии; хотя бы одно из двух
    "category": "oil_radiator",
    "availability": "in_stock",
    "brand": "Ballu", "title": "Vario BOH/CB-09",
    "card":  {"path": "oil/AV-100234.png",     // ОТНОСИТЕЛЬНЫЙ путь внутри cards_root
              "sha256": "<64 hex>",
              "provenance": "generated",       // единственное допустимое значение
              "generator": "fotogen", "job_id": "job-771"},
    "usp":   {"kind": "generator_override",    // либо "feed_description"
              "text": "…", "sha256": "<64 hex от text>",
              "source_ref": "avito-descriptions/manifest.json#BOH-CB"},
    "price": {"final": 9990, "currency": "RUB",
              "kind": "exact",                 // либо "series_from"
              "already_marked_up": true},      // цена уже конечная; повторной наценки не будет
    "models": [{"model": "BOH/CB-07", "price": 9990}]   // обязателен для series_from
  }]
}
```

Категории партии: `oil_radiator`, `heat_gun_electric`, `heat_gun_gas`, `heat_gun_diesel`,
`underfloor_heating`, `thermostat`, `water_heater`, `heat_pump`,
`inverter_air_conditioner`. Дополнительно принимаются `convector_electric` и `breezer` —
они помечаются `review_required` и выводятся в сводке отдельной группой (владелец просил
их «проверить», а не включить по умолчанию). `generator` и `voltage_stabilizer` отклоняются
явно.

### Почему позиция может быть отклонена

`category_denied` · `category_unknown` · `not_in_stock` · `identity_missing` ·
`title_missing` · `card_not_generated` (в т.ч. фото из XML-фида) · `card_path_is_url` ·
`card_path_not_relative` · `card_path_traversal` · `card_path_symlink` · `card_path_escape` ·
`card_file_missing` · `card_empty` · `card_too_large` · `card_not_an_image` (проверка по
сигнатуре файла, не по расширению) · `card_sha_mismatch` · `price_not_final` ·
`price_currency` · `price_invalid` · `price_kind_unknown` · `series_needs_two_priced_models` ·
`series_from_price_mismatch` · `exact_price_mismatch` · `usp_kind_unknown` ·
`usp_sha_mismatch` · `usp_source_ref_missing` · `usp_platform_mention_ambiguous` ·
`usp_empty_after_cleanup` · `caption_too_long` · `batch_limit`.

Структурные проблемы (`schema_version`, пустой `batch_id`, отсутствующий `feed.sha256`,
неабсолютный `cards_root`, **дубли `source_id`/`sku`**) отклоняют партию целиком: дубль
идентичности — это неоднозначность, а не мелочь.

## 3. Две идентичности

- `product_key = avito|<source_id>` — ключ товара в `ConfirmStore`. Хеши в него НЕ входят:
  иначе смена цены или УТП породила бы новый ключ и обошла защиту `pending`/`rejected`/
  `published`.
- `import_key` — ревизия (source_id + хеши карточки, УТП, цены, фида). Живёт в журнале
  доставок и защищает от повторной отправки той же ревизии, в том числе при конкурентных
  запусках (`UNIQUE`-резервирование в SQLite — авторитетный механизм, не файловый лок).

Изменившиеся хеши **не** позволяют обойти прошлое решение владельца: сначала проверяется
состояние товара, и только потом ревизия.

Сверх этого проверяются **«родные» ключи** товара — `series_key` и `sku`. Под ними тот же
товар мог попасть в очередь старым конвейером: в рабочей БД сотни строк вида
`breeze|alfacool|apus`. Без такой проверки товар, уже ждущий решения или опубликованный,
получил бы второй пост под ключом `avito|…`. Пропуск помечается причиной
`legacy_confirm_state:<статус>` или `legacy_published`.

## 4. Запуск

### 4.0. Собрать манифест из инвентаря

Манифест не пишут руками: его собирает `avito_manifest_build` из инвентаря живой
выгрузки (`state/avito-live-inventory.json` — сверка фида, Bridge-цен и очередей
генератора, с `feed_sha256` как версией источника цен).

```bash
PYTHONPATH=src .venv/bin/python -m content_factory.ingest.avito_manifest_build \
  --inventory state/avito-live-inventory.json \
  --cards-root /opt/oasis/staticfiles/avito-cards \
  --batch-id avito-2026-08-31 \
  --out state/avito-batch-manifest.json
```

Печатает, сколько позиций вошло и почему отсеяны остальные; сводка причин уезжает в
манифест (`excluded`) и попадает в отчёт владельцу. Две вещи модуль правит по данным,
а не по догадке:

- **тип товара** берётся из названия модели: у водонагревателей заголовок выгрузки
  безликий («Оборудование Ecostar Smile»), а внутри категории «тёплый пол» лежат
  терморегуляторы, подписанные тёплым полом;
- **перечень цен вырезается из описания** — цены печатаются из `price`/`models`, а тот же
  список внутри текста это снимок фида, который после обновления цен начнёт ему
  противоречить внутри одного поста. Заодно из блока «Характеристики» убираются строки
  со значением «Нет» и служебные идентификаторы; сами значения не переписываются.

> **Git Bash на Windows.** Абсолютный путь `/opt/...` в аргументах MSYS перепишет в
> windows-путь, и все позиции отвалятся как `card_outside_cards_root`. Запускать с
> `MSYS_NO_PATHCONV=1`.

Запускать всё это надо **на VPS**: там карточки, общая state-БД и `.env` работающего
бота. Прогон с локальной машины бесполезен — при approve бот не найдёт файл по
`card_path`. Долгую партию — через `setsid nohup … &`, чтобы обрыв SSH не убил её
посередине.

Dry-run (по умолчанию; сеть и state-БД не трогаются вовсе):

```bash
python -m content_factory.ingest.avito_import \
  --manifest /opt/content-factory/state/avito-batch-2026-08-30.json \
  --state-db /opt/content-factory/state/content_factory.db \
  --media-dir /opt/content-factory/state/avito-cards \
  --limit 12
```

Отправка превью в review-чат (только после проверки dry-run):

```bash
python -m content_factory.ingest.avito_import \
  --manifest … --state-db … --media-dir … \
  --telegram-env /opt/content-factory/.env \
  --send-review --limit 12 --min-interval 3
```

`--telegram-env` читает `TELEGRAM_BOT_TOKEN`, `TELEGRAM_REVIEW_CHANNEL_ID`,
`TELEGRAM_CHANNEL_ID`, `TELEGRAM_OWNER_CHAT_ID` (fallback `FOTOGEN_CHAT_ID`). Значения
никуда не печатаются: в сводке id канала маскируется до последних четырёх символов.

### Предполётные отказы (до любого сетевого вызова)

- пустой токен;
- review-чат совпадает с каналом публикации;
- review и канал заданы в **разных формах** (числовой id против `@alias`) — различие не
  доказуемо, приведите оба к одному виду;
- пуст `TELEGRAM_OWNER_CHAT_ID` и `FOTOGEN_CHAT_ID`: в `bot/run.py` гейт выглядит как
  `if owner and frm != owner`, то есть при пустом owner кнопку ✅ может нажать любой
  участник review-канала.

По итогу прогона владельцу уходит в личку (`TELEGRAM_OWNER_CHAT_ID`, fallback
`FOTOGEN_CHAT_ID`) сводка: сколько отправлено, что пропущено и по каким причинам, что не
вошло в партию ещё на сборке манифеста, — плюс полный отчёт JSON-файлом. Отчёт
вспомогателен: его сбой не отменяет уже отправленную партию, а попадает в `report_error`.
Review-чат остаётся чистым потоком карточек.

Партиями по 12 — не техническое ограничение, а требование к читаемости ревью и защита от
анти-флуда Telegram. Порядок детерминированный (категория → цена → ключ), поэтому волны
воспроизводимы, а возобновление обеспечивается защитой статусов.

## 5. Изображения

Карточка копируется в `--media-dir/<batch_id>/avito_<source_id>.<png|jpg>`, хеш копии
перепроверяется, и в `ConfirmStore` пишется **абсолютный путь копии**. Причины:

- бот при approve читает файл по этому пути из своего рабочего каталога;
- команда `/regen` в существующем боте делает `unlink(card_path)` — уничтожить она может
  только копию, оригинал готовой карточки останется на месте (перегенерация запрещена).

Для импортированных постов `/regen` бессмысленен (задачи генератора для них нет): если
карточка не нравится — ❌ «Отклонить».

## 6. Подпись

Первая строка — название, вторая — цена: `publish/orders.py::item_summary` берёт ровно эти
две строки для карточки клиенту и для лида по кнопке «📩 Заказать». Дальше — таблица
моделей (для серии), УТП и CTA.

- «от» показывается только у серии с ≥2 моделями с ценами и всегда равно минимуму по
  **полному** включённому списку; сокращение таблицы видно читателю («и ещё N моделей»).
- Лимит 1024 считается в кодовых единицах UTF-16 по видимому тексту (как считает Telegram)
  и проверяется дважды: для сохранённой подписи и для неё же с пометкой ревью.
- Переполнение сокращается ЦЕЛЫМИ блоками: хвост УТП → строки таблицы (минимум 2) → CTA →
  таблица целиком. Число, единицу и цену обрезать нельзя; если не влезает даже шапка с
  ценой — позиция отклоняется (`caption_too_long`), а не режется.
- Всё подставляемое экранируется; HTML из описаний фида не пробрасывается.
- Avito-призывы вырезаются целыми блоками. Блок, который упоминает площадку, но призывом
  не является, — неоднозначность: позиция отклоняется, а не переписывается.

## 7. Ошибки доставки и сверка

| Событие | Журнал | `ConfirmStore` | Партия |
|---|---|---|---|
| `ok: true` + `message_id` | `sent` | `pending` | продолжается |
| `ok: false` (напр. chat not found) | `send_failed` | `send_failed` | продолжается, позиция пригодна к повтору |
| 429 с `retry_after` | пауза, ровно одна повторная попытка | — | продолжается |
| 429 без `retry_after` | `send_failed` | `send_failed` | продолжается |
| Нет соединения (`ConnectError`) | `send_failed` | `send_failed` | продолжается |
| Таймаут/обрыв после отправки, 5xx, `ok: true` без `message_id` | `send_unverified` | **остаётся `pending`** | **останов** |

`pending` при неоднозначности сохраняется намеренно: сообщение могло дойти, и кнопка ✅
обязана работать (существующий `/approve` принимает только `pending`). Автоматической
переотправки после неоднозначности не бывает ни в каком режиме — три подряд однозначных
отказа тоже останавливают партию.

Сверка — глазами, потому что второй поллер бота запрещён:

```bash
python -m content_factory.ingest.avito_import --state-db … --reconcile
# нашли карточку в review-канале:
python -m content_factory.ingest.avito_import --state-db … \
  --resolve-unverified <import_key> --outcome delivered --message-id 12345
# карточки в канале нет:
python -m content_factory.ingest.avito_import --state-db … \
  --resolve-unverified <import_key> --outcome not-delivered
```

`delivered` записывает реальный `message_id` и оставляет строку `pending`;
`not-delivered` снимает `pending` в `send_failed` и разрешает повтор.

## 8. Осмотр состояния и откат

```bash
sqlite3 state/content_factory.db \
  "SELECT key,status,channel,substr(card_path,-40) FROM awaiting WHERE key LIKE 'avito|%';"
sqlite3 state/content_factory.db \
  "SELECT product_key,status,review_message_id,error FROM avito_review_deliveries;"
```

Штатный откат — **через бота**: ❌ «Отклонить» под превью (или `/reject avito|<id>`).
Ключи `avito|*` попадают в `blocked_keys()` планировщика — это ожидаемо и безвредно:
это не ключи серий, конвейер их не выбирает.

Удаление строк в БД — не рутина, а исключительный ремонт: только с бэкапом файла БД,
при остановленном `cf-bot` и по решению владельца. Массово чистить старую очередь нельзя.

## 9. Границы

- Публикация в публичный канал разрешения не имеет: её делает только владелец кнопкой.
- Права на подтверждение не расширяются: список тех, кто может нажимать ✅, задаётся
  существующим гейтом в боте и этой интеграцией не трогается.
- Постоянный импорт по таймеру — только после отдельной проверки владельцем; `systemd` и
  `nginx` этой задачей не меняются, деплой не выполняется.
- Исправленная версия уже отклонённого или опубликованного поста импортёром не
  поддерживается намеренно: это перезапись решения владельца. Такой случай требует
  отдельного решения и явной новой идентичности.

дедуп по «родным» ключам; сборка манифеста из инвентаря; отчёт владельцу.

## 11. Прогон 31.08.2026

Партия `avito-2026-08-31`: **44 поста** — 29 водонагревателей и бойлеров, 9 тёплых полов
и терморегуляторов, 6 масляных радиаторов. `message_id` 3062–3105, ошибок и неоднозначных
доставок нет, все 44 стоят `pending` и ждут кнопки владельца.

Не вошли **160 позиций**, все по одной причине — `no_generated_card`: карточки для них
ещё не сгенерированы. В том числе целиком отсутствуют инверторные сплит-системы (86),
радиаторы отопления (17), электроконвекторы (15), тепловые пушки (11) и отопительные
котлы (11). Фото поставщика из фида карточкой не считается, поэтому подставлять их
вместо сгенерированных нельзя — эти категории ждут прогона генератора.
